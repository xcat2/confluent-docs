# 4.0.0 Confluent release

4.0.0 is the asyncio release. eventlet and greenlet are gone from the server, and so is
pyghmi, replaced by `aiohmi`, an async fork that now lives inside `confluent_server`.

Read the breaking changes first. The one most likely to catch you is
`hardwaremanagement.method`, which no longer defaults to `ipmi`.
<!-- more -->

## Breaking changes

### `hardwaremanagement.method` now has to be set

!!! warning "Action required on upgrade"

    An unset `hardwaremanagement.method` used to mean `ipmi`. It now means `null`, which
    implements no hardware management at all. Any node that relied on the old default gets no
    power, sensor, or inventory commands until you set the attribute:

    ```
    nodeattrib <noderange> hardwaremanagement.method=ipmi
    ```

The attribute also declares its valid values now. A typo is rejected when you set it, rather
than turning into a plugin error the next time you run a command.

### EL7 and EL8 are no longer management server targets

The server needs Python 3.9 or newer, and the RPM spec no longer carries dependency sets for
EL7 or EL8. EL9 and EL10 are the packaged Enterprise Linux targets. This is only about the
machine running confluent. The deploy scripts that run on nodes are still checked against
Python 3.6, so SLES 15 and EL8 nodes remain deployable.

### Python 3.13 needs a crypt module from somewhere else

!!! warning "The server will not start without one"

    Python 3.13 dropped `crypt` from the standard library, and confluent hashes stored
    credentials with it. The server tries `crypt`, then `legacycrypt`, then `crypt_r`, and
    exits if it finds none of them.

The RPM recommends `python3-legacycrypt` rather than requiring it, because some 3.13
distributions package no candidate at all, so you may have to supply one yourself.

### User accounts can only be managed from the management server

Creating, changing, or deleting a confluent user or usergroup now needs a local connection on
the management server, as root or as the confluent user. Logging in over HTTP or the web UI
gives read-only access to the user list, whatever rights the account has.

A second restriction covers file paths. A confluent user with no matching operating system
account can no longer point confluent at an arbitrary path, whether the file is a firmware
image, a license, media to attach, or a download target. Those users get
`/var/lib/confluent/client_assets/` and `/var/lib/confluent/private/identity_images` and
nothing else, because confluent has no OS identity to check ownership against. Container
deployments are where this shows up, since confluent users there usually have no system
account.

### The server will not start without `-f`

There is no background mode left. `confluent` exits with "-f is now required" if you leave the
flag off, because forking breaks the asyncio thread executor. `confluent.service` is a
`Type=notify` unit and passes the flag, so a systemd start is unaffected. Anything that starts
the server by hand has to pass it too, including the packaged sysvinit script, which does not.

### The dependency set changed

Out: `pyghmi`, `eventlet`, `greenlet`, `pycryptodomex`, `paramiko`, `dnspython`,
`websocket-client`. In: `aiohttp`, `yarl`, `asyncssh`, `cryptography`. The packages handle the
swap. From a source checkout, install the new set by hand.

### Long-polling in the HTTP API was removed

The deprecated long-poll behavior went out with the eventlet HTTP stack. Clients on the current
async notification path are unaffected.

## Hardware management

### Fix: Redfish and IPMI correctness pass

Redfish writes send `If-Match` where they need to, a write drops the URL cache, and confluent
addresses accounts by the id the BMC gave them. An unsupported operation reports a message
instead of a traceback.

On the IPMI side, one session serves several callers without one of them closing it for the
rest. SEL decoding survives kernel panic records and malformed bodies, SDR partial reads stop
retrying codes the BMC will never satisfy, and a BMC that lacks a feature is told apart from a
request that failed.

### Enhancement: `nodeeventlog` reads every log a platform keeps

Some platforms publish several logs, and some publish their event log somewhere other than
where confluent looked. Both are found now. You can ask for a single log rather than all of
them, and the command sets an exit code when a read fails.

### Enhancement: MegaRAC discovery and firmware updates

Discovery works on recent MegaRAC firmware. The initial password state is handled rather than
tripped over, and Redfish firmware updates now work against AMI MegaRAC.

### New: Raritan PDU support

`hardwaremanagement.method=raritan` is a new plugin. It holds a session and what it learned
about the PDU across requests. Sensor reads go out in bulk where the PDU supports it, and the
inlet readings now join the same bulk request as the outlet readings instead of taking a call
each, which shaves a few seconds off a sweep.

### New: EUREKA chassis support

Confluent discovers the MEGWARE EUREKA chassis and talks to it through a new Redfish OEM
handler. A manager address can name a port with colon notation.

### Enhancement: larger receive buffer for discovery scans

The packaged sysctl drop-in raises `net.core.rmem_max` from 2 MB to 4 MB.

## OS deployment

### New: SUSE 16 groundwork

Confluent recognizes SLES 16 and Leap 16 media and files it under a new `suse16` profile
category. The agama based install scripts, `initprofile.sh`, the shared function library, and
identity image support are all in the tree. One piece is missing. The shipped `suse16` profile
carries no `profile.yaml`, so an import needs one supplied before a deployment will run.

### Breaking: ProxyDHCP honors `deployment.useinsecureprotocols`

ProxyDHCP used to serve a boot without consulting that attribute, unlike the regular DHCP path.
It now refuses when the attribute is unset or `never`, so a node relying on ProxyDHCP for plain
PXE needs it set to `firmware` or `always`. The refusal is logged once every 90 seconds per MAC
address rather than on every retry.

### New: EL10 and Ubuntu 26.04 diskless

`imgutil` can capture EL10, diskless runtime files get proper SELinux labels on Enterprise
Linux, and Ubuntu 26.04 has a diskless profile.

### New: `deployment.storage` and better install disk selection

The new `deployment.storage` attribute takes a device name or a generic hint such as `m2`. The
selection logic behind it recognizes SATA M.2 drives now, handles 7mm disks with no RAID
volume, and puts M.2 form factor drives high in the priority list by default.

### Fix: syncfiles preserves ownership and reports failures

`syncfileclient` keeps ownership and permissions without disturbing parent directories, and it
applies chown before chmod. A failure gets reported rather than discarded. The thirteen
per-profile copies were folded into one shared copy, so a fix reaches every profile at once.

### Enhancement: faster untethered diskless boot

An untethered or uncompressed diskless boot used to extract its root filesystem with `cp -a`,
one file at a time. It now uses `unsquashfs`, which extracts in parallel, and falls back to
`cp` if the tool is missing or the extraction fails. Multipart images go the same route. The
image needs `squashfs-tools`, now in the EL9 and EL10 package lists and the Ubuntu initramfs
hook, and `imgutil` names the package when a capture target lacks it.

### New: `osdeploy fetch`

New subcommand that downloads install media for Rocky, AlmaLinux, Ubuntu, and Debian, on
x86_64 and aarch64. Where the distribution publishes one, confluent checks the detached GPG
signature over the checksum file and then the ISO's SHA256. There is progress output and tab
completion.

### Fix: deployment ignores a proxy in the environment

A proxy configured in the environment no longer intercepts the calls a deploying node makes
back to its management server. `apiclient` clears the proxy variables, the shared `functions`
library passes `curl -x ""`, and `setupssh` and `misc/prepadopt.sh` unset `http_proxy` and
`https_proxy`.

### New: `net.extra_settings`

Passthrough network settings, as semicolon-delimited key=value pairs in the native syntax of
the deployed OS: nmcli properties, netplan keys, or wicked ifcfg variables.

### Enhancement: TPM PCR sealing

`encryptboot` accepts explicit TPM2 PCRs, and confluent uses `systemd-cryptenroll` where it is
available. Ubuntu now seals to PCRs at first boot rather than during install, when the
measurements are stable.

### New: secure boot key enrollment

Enrolling a machine owner key means answering the firmware's MOK Manager prompts by hand, once
per node. `misc/secureboot` now holds the pieces to script it. `pushmok.sh` copies a key to the
node, imports it with `mokutil`, reboots, and drives the MOK Manager screens through
`nodeconsole` automation, taking the password from `MOKPASS` in the environment.
`enrollmok.nca`, `deletemok.nca`, and `purgemok.sh` cover the other operations. MokManager
itself now goes onto genesis and `imgutil` boot media, and `mokutil` is in the genesis
initramfs.

### New: stateless boot reports completion

Diskless boots report a `booted` status with a timestamp, so `nodedeploy` can tell a node that
finished from one that is still coming up.

### New: deployment state carries a timestamp

`deployment.state_last_updated` is a new attribute. It holds an ISO 8601 timestamp at second
resolution, local time with an offset, written whenever a profile reports a state change.
`nodedeploy` prints it after the state. The `updated:` label it used to carry is gone, since it
read as an OS update rather than a state change.

### New: cross-architecture image builds

`imgutil build --arch` builds an image for an architecture other than the host's. It needs a
statically linked qemu-user emulator for the target, registered in `binfmt_misc` with the `F`
flag.

### New: diskless images can boot from local media

Initial support for booting a confluent diskless image from attached media rather than over
the network. It lives in the Ubuntu diskless profiles and the matching `imgutil` initramfs
hook. The boot media carries MokManager, so secure boot key enrollment works from there.

## Console

### New: `nodeconsole -v`

Remote video console in the terminal. Confluent carries its own VNC client for it rather than
depending on an external one. Keyboard input, focus changes, desktop resize, and power commands
all work from inside the session.

### Enhancement: vtbufferd lifecycle

vtbufferd talks over a unix domain socket now, and confluent starts it on first use rather than
at startup. If it exits, confluent will not respawn it more than once every 30 seconds.

## Security

### New: nodes can request a TLS certificate

A node can ask confluent for a TLS certificate through `/self/tlscert`. The new
`pubkeys.tls_lifetime` attribute sets how long it stays valid, 47 days by default.

### Enhancement: webauthn and passkeys

Passkey support runs on aiohttp now and follows the webauthn defaults. A passkey can also
supply the username.

### Fix: license upload hardening

Confluent reduces a license filename to its basename so it cannot traverse paths, and refuses
to overwrite an existing file.

## Client and tooling

### Fix: the CLI tools report failures

Client commands print an error rather than a traceback followed by usage text, and set an exit
code when a read fails. `nodeshell` gained a connect timeout.

### New: `confluentdbutil` additions

YAML for dump and restore alongside JSON, `-x` to exclude an attribute and everything below
it, an alternate directory to operate on, and a `showattrib` subcommand. Restore gives a clear
error on a mismatched dump format or a nonexistent tenant instead of an obscure failure.

### New: `confluent2dnsmasq`

Generates dnsmasq DHCP configuration from confluent. It picks the listen address off `ip route`
and warns about entries that conflict with one another.

### Docs: man pages

Commands that had no man page have one now, including `confluent2ansible`, `confluent2dnsmasq`,
`confluent2lxca`, `confluent2xcat`, `dir2img`, `nodecertutil`, `noderename`, and
`nodegrouprename`.

## Other fixes

SSDP no longer ignores packets that do not closely follow another. Software RAID creation works
with newer mdadm and with hostname-prefixed md device names. `imgutil` propagates image build
failures instead of reporting success. A node cannot be named the same thing as a group, and
proxmox handles an unreachable host and a powered down VM without hammering it.
