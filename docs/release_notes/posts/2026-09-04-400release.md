# 4.0.0 Confluent release

4.0.0 is a large internal rewrite. The server core was rebuilt on a new way of handling many
nodes at once, and the code that talks to BMCs with it. Commands work the same day to day, but
which platforms confluent runs on, what it needs installed, and a few defaults all changed.

Read the breaking changes first. The one most likely to catch you is
`hardwaremanagement.method`, which no longer defaults to `ipmi`.

## Breaking changes

### `hardwaremanagement.method` now has to be set

!!! warning "Action required on upgrade"

    An unset `hardwaremanagement.method` used to mean `ipmi`. It now means `null`, which
    implements no hardware management at all. Any node that relied on the old default gets no
    power, sensor, or inventory commands until you set the attribute:

    ```
    nodeattrib <noderange> hardwaremanagement.method=ipmi
    ```

The attribute also declares its valid values now. A typo is rejected when you set it, rather
than turning into a plugin error the next time you run a command.

### EL7 and EL8 are no longer management server targets

The server needs Python 3.9 or newer, and there are no longer packages for EL7 or EL8. EL9 and
EL10 are the packaged Enterprise Linux targets. This is only about the machine running
confluent. Nodes are unaffected, so SLES 15 and EL8 nodes remain deployable.

### Python 3.13 needs a crypt module from somewhere else

!!! warning "The server will not start without one"

    Python 3.13 dropped `crypt` from the standard library, and confluent hashes stored
    credentials with it. Install `python3-legacycrypt`, or `crypt_r` where that is what your
    distribution ships.

The RPM recommends `python3-legacycrypt` rather than requiring it, because some 3.13
distributions package no candidate at all, so on those you have to supply one yourself.

### User accounts can only be managed from the management server

Creating, changing, or deleting a confluent user or usergroup now needs a local connection on
the management server, as root or as the confluent user. Logging in over HTTP or the web UI
gives read-only access to the user list, whatever rights the account has.

A second restriction covers file paths. A confluent user with no matching operating system
account can no longer point confluent at an arbitrary path, whether the file is a firmware
image, a license, media to attach, or a download target. Those users get
`/var/lib/confluent/client_assets/` and `/var/lib/confluent/private/identity_images` and
nothing else, because confluent has no OS identity to check ownership against. Container
deployments are where this shows up, since confluent users there usually have no system
account.

### The dependency set changed

- Out: `pyghmi`, `eventlet`, `greenlet`, `pycryptodomex`, `paramiko`, `dnspython`,
`websocket-client`
- In: `aiohttp`, `yarl`, `asyncssh`, `cryptography`
Upgrading pulls the new set in, but a site that mirrors its own repositories needs them there first.

### Long-polling in the HTTP API was removed

The deprecated long-poll behavior went out with the old HTTP stack. Clients on the current
notification path are unaffected.

## Discovery enhancements

### 'Aggressive' discovery

nodediscover has a new '-a' argument.  This will more aggressively probe local network segments and discovery data will be filled
with types otherwise missed:
- generic-ssh : anything running ssh at all
- generic-https : anything running an https server
- generic-redfish : An otherwise uncategorized Redfish endpoint
- nvos-switch : Nvidia equipment running NVOS such as Infiniband and NVLink switches

### New discovery onboarding support

Confluent can onboard NVOS systems (currently handles password change only) and attempt to onboard generic redfish implementations in the same way as it
onboards XCC3 systems.  This has been tested with some BMCs, but results are not guaranteed.

For NVOS, secret.adminpassword is used to indicate the desired admin password to set.  For generic-redfish, secret.initialhardwaremanagementuser and secret.initialhardwaremanagementpassword are used to indicate the firmware initial credentials if not already at desired value.

### Better handling of routed discovery

The 'aggressive' generic targets are invoked for routed targets.  IP address may be used in contexts where MAC address is not available.

### Support for fixed address DHCP offers

If a node has net.hwaddr set and net.lease_time specified, then it will offer up static DHCP offers for nodes with fixed addresses in an arbitrary fashion.
Particularly useful if wanting to keep something like an NVOS switch DHCP managed, as the mac address will be recorded by discovery.

### MegaRAC discovery and firmware updates

Discovery and firmware updates have been updated and extended for MegaRAC implementations.

## Hardware management

### `nodeconfig` now indicates pending status where possible, with a `-p` option to focus on such settings

This lets the operator know which settings are not yet actually active, according to the firmware.

### `nodesensors` with redfish may be significantly faster

Where confident, it will request sensors in bulk.

### Hardware management command general fixup

A broad pass over the Redfish and IPMI backends. BMC user accounts can be deleted and their
passwords changed again, `nodemedia` insertion works, `nodefirmware` names categories beyond
core, adapters, and disks, and `nodereseat`, `nodesetboot`, `nodeidentify`, and `nodestorage`
work where they used to error out. An operation a platform does not support now says so
instead of printing a traceback, and `nodeinventory` tells you when a filter matched nothing.

`nodeeventlog` survives a kernel panic entry and other malformed records, and a sensor sweep no
longer stalls retrying reads the BMC will not serve.

### `nodeeventlog` reads more logs of devices, and allows selective log requests

Some platforms publish several logs, and some publish their event log somewhere other than
where confluent looked. Both are found now. You can ask for a single log rather than all of
them, and the command sets an exit code when a read fails.

### Raritan PDU support has been added

`hardwaremanagement.method=raritan` is now available plugin, covering outlet power control, sensors,
and inventory.

### EUREKA chassis support has been added

Confluent discovers and manages the MEGWARE EUREKA chassis. A manager address can name a port,
as `address:port`.

## OS deployment

### SUSE 16 support has been added

SUSE 16 can now be imported and deployed.

### EL10 and Ubuntu 26.04 improvements

`imgutil` can capture EL10, diskless runtime files get proper SELinux labels on Enterprise
Linux, and Ubuntu 26.04 has a diskless profile.

### `deployment.storage` introduced to allow more steering of the auto-disk selection logic

The new `deployment.storage` attribute takes a device name or a generic hint such as `m2`. The
selection logic behind it recognizes SATA M.2 drives now, handles 7mm disks with no RAID
volume, and puts M.2 form factor drives high in the priority list by default.

### Fix: syncfiles preserves ownership and reports failures

`syncfileclient` keeps ownership and permissions without disturbing parent directories, and it
applies chown before chmod. A failure gets reported rather than silently discarded.

### Untethered image unpacking can be optionally sped up

An untethered or uncompressed diskless boot extracts its root filesystem with `unsquashfs` now
instead of copying it file by file, which is considerably faster, and falls back to copying if
that fails. A custom image needs `squashfs-tools` present, and `imgutil` names the package when
a capture target lacks it.

### `osdeploy fetch` Added to help download a number of Linux distributions

New subcommand that downloads install media for Rocky, AlmaLinux, Ubuntu, and Debian, on
x86_64 and aarch64. It verifies the GPG signature and checksum where the distribution publishes
them, and shows progress. Tab completion included.

### Improved bypass of proxy environment variables

A proxy set in the environment no longer intercepts the calls a deploying node makes back to
its management server. Node adoption ignores it too.

### `net.extra_settings` to passthrough network settings

Passthrough network settings, as semicolon-delimited key=value pairs in the native syntax of
the deployed OS: nmcli properties, netplan keys, or wicked ifcfg variables.

### Optional TPM PCR sealing for encrypted boot

`encryptboot` accepts explicit TPM2 PCRs, and confluent uses `systemd-cryptenroll` where it is
available. Ubuntu now seals to PCRs at first boot rather than during install, when the
measurements are stable.  This allows users to opt into more fragile, but more hardened
auto-unlock of encrypted volumes at boot.

### Genesis updates

Genesis is based on the latest Alma 10.x packages.  Additionally, an ARM package is provided.

### Stateless boot reports completion

Diskless boots report a `booted` status with a timestamp, so `nodedeploy` can tell a node that
finished from one that is still coming up. `deployment.state_last_updated` is a new attribute holding the time a profile last reported a
state change. `nodedeploy` prints it after the state, without
the `updated:` label it used to carry, which read as an OS update.

### Cross-architecture image builds

`imgutil build --arch` builds an image for an architecture other than the host's. It needs a
statically linked qemu-user emulator for the target, registered in `binfmt_misc`.  It will autodetect, when possible, if the source indicated requires it.  Note that this is going to be painfully slow for compute intensive tasks in imgutil exec.

### Diskless images can boot from local media

Initial support for booting a confluent diskless image from attached media rather than over
the network. It covers the Ubuntu diskless profiles so far.

## Console

### Node video console access from terminal (`nodeconsole -tv` and '-o' to record to '.mp4')

Remote video console in the terminal, with no external dependency to install. Keyboard input,
focus changes, desktop resize, and power commands all work from inside the session.  Video output
when requested works asynchronously from the display, resulting in smoother performance in video
even if the ssh access is slow enough to impose stuttering.

## Security

### Secureboot support for PXE

iPXE is updated to 2.0.0 and confluent is changed to use the iPXE shim and indicate OS shims to
allow SecureBoot enabled PXE.

### Secure boot key enrollment assistance

Genesis has mokmanager added and samples are available to use nodeconsole automation to handle
MOK key enrollment in an unattended fashion.  Useful if wanting to do Secureboot with compiled modules.

### SSH access from web UI now uses the certificates by default

Before, it only supported confluent DB stored known hosts.  It now consults the /etc/ssh/ssh_known_hosts as well.

### Nodes can now request a TLS certificate

A node can ask confluent for a TLS certificate through `/self/tlscert`. The new
`pubkeys.tls_lifetime` attribute sets how long it stays valid, 47 days by default.

### Add auth protocol selection to SNMP and support AES256 privacy

For SNMP, there is more flexibility in the auth and privacy protocols.

### Webauthn/Passkey enhancement

Passkeys may now be used to login without specifying username first

## Client and tooling

### Fix: the CLI tools report failures

Client commands print an error rather than a traceback followed by usage text, and set an exit
code when a read fails. `nodeshell` gained a connect timeout.

### `confluentdbutil` enhancements

YAML for dump and restore alongside JSON, `-x` to exclude an attribute and everything below
it, an alternate directory to operate on, and a `showattrib` subcommand. Restore gives a clear
error on a mismatched dump format or a nonexistent tenant instead of an obscure failure.

### `confluent2dnsmasq` added to inject DHCP configuration

Generates dnsmasq DHCP configuration from confluent. It picks the listen address off `ip route`
and warns about entries that conflict with one another.  This is not required, but can be helpful
if wanting to have dnsmasq own dynamic range but also have confluent managed fixed assignments.

### Documentation enhancements

Commands that had no man page have one now, including `confluent2ansible`, `confluent2dnsmasq`,
`confluent2lxca`, `confluent2xcat`, `dir2img`, `nodecertutil`, `noderename`, and
`nodegrouprename`.

## Other fixes

SSDP no longer ignores packets that do not closely follow another. Software RAID creation works
with newer mdadm and with hostname-prefixed md device names. `imgutil` propagates image build
failures instead of reporting success. A node cannot be named the same thing as a group, and
proxmox handles an unreachable host and a powered down VM more gracefully.
