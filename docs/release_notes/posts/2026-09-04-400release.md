# 4.0.0 Confluent release

4.0.0 is the asyncio release. eventlet and greenlet are gone from the server, and so is
pyghmi, replaced by `aiohmi`, an async fork that now lives inside `confluent_server`. Around
800 commits went into that port and the work that came with it, so these notes are grouped
rather than listed flat.

Read the breaking changes before upgrading a running deployment. One of them will change the
behavior of existing nodes.

## Breaking changes

### `hardwaremanagement.method` now has to be set

An unset `hardwaremanagement.method` used to mean `ipmi`. It now means `null`, and hardware
management operations are not implemented for the node. Any node that relied on the
old default needs the attribute set before power, sensor, or inventory commands work again:

```
nodeattrib <noderange> hardwaremanagement.method=ipmi
```

The attribute now declares its valid values, so a typo is rejected when you set it instead of
surfacing later as a confusing plugin error.

### EL7 and EL8 are no longer management server targets

The server needs Python 3.9 or newer, and the RPM spec no longer carries dependency sets for
EL7 or EL8. EL9 and EL10 are the packaged Enterprise Linux targets. This is only about the
machine running confluent: the deploy scripts that run on nodes are still checked against
Python 3.6, so SLES 15 and EL8 nodes remain deployable.

### The dependency set changed

Out: `pyghmi`, `eventlet`, `greenlet`, `pycryptodomex`, `paramiko`, `dnspython`,
`websocket-client`. In: `aiohttp`, `yarl`, `asyncssh`, `cryptography`. The packages handle this
for you. If you run from a source checkout, install the new set by hand.

### Long-polling in the HTTP API was removed

The deprecated long-poll behavior is gone along with the eventlet HTTP stack. Clients using
the current async notification path are unaffected.

### The service no longer daemonizes itself

`confluent.service` is a `Type=notify` unit now and the process stays in the foreground.
Anything that started the daemon by hand and expected it to background itself needs adjusting.

### Confluent-managed users are local-socket only

Adding or modifying confluent user accounts is now restricted to `skipauth` users, meaning
root or confluent over the unix domain socket. Authenticated users over HTTP can no longer
create or manipulate accounts. Non-system users also lost the open ended access they used to
have.

## Hardware management

### aiohmi replaces pyghmi

The IPMI and Redfish client is vendored into the tree as `aiohmi` and is async throughout.
Confluent no longer depends on the pyghmi package at all.

### Raritan PDU support

`hardwaremanagement.method=raritan` is a new plugin. It keeps a session and information about
the PDU across requests, uses the bulk read facility where the PDU offers one, and defers the
inlet sensor so a sensor sweep finishes sooner.

### EUREKA chassis support

Discovery handler plus a Redfish OEM implementation for the MEGWARE EUREKA chassis, including
port discovery via colon notation on the manager address.

### MegaRAC improvements

Discovery works on recent MegaRAC firmware, the initial password state is handled rather than
tripped over, and Redfish firmware updates now work against AMI MegaRAC.

### `nodeeventlog` reads every log a platform keeps

Platforms that publish more than one log, or publish their event log somewhere other than
where confluent looked, are now enumerated properly. A single log can be selected rather than
dumping all of them, and the command sets an exit code when a read fails.

### A correctness pass over Redfish and IPMI

This is the least glamorous and probably the most valuable part of the release. Redfish writes
send `If-Match` where they need to, the URL cache is dropped on write, accounts are addressed
by the id the BMC actually gave them, and every unsupported operation reports a message
instead of a traceback. On the IPMI side, sessions are shared correctly between callers, SEL
decoding survives kernel panic records and malformed bodies, SDR partial reads stop retrying
codes the BMC will never satisfy, and a BMC that lacks a feature is told apart from a request
that failed.

### Switch handling

ENOS health data is reused rather than re-fetched, and the NXOS and SRLinux plugins were ported
to the async model along with LLDP and MAC map gathering.

## OS deployment

### SUSE 16 deployment

SLES 16 and Leap 16 are deployable through agama, with a shared function library, an
`initprofile` for the SUSE profiles, and identity image support.

### EL10 and Ubuntu 26.04 diskless

`imgutil` can capture EL10, diskless runtime files get proper SELinux labels on Enterprise
Linux, and Ubuntu 26.04 has a diskless profile.

### `deployment.storage` and better install disk selection

The new `deployment.storage` attribute takes a device name or a generic hint such as `m2`. The
selection logic behind it was reworked to recognize SATA M.2 drives, handle 7mm disks without a
RAID volume, and treat M.2 form factor drives as a high priority by default.

### Diskless images can boot from local media

Initial support for booting a confluent diskless image from attached media rather than over the
network, currently in the Ubuntu diskless profiles and the matching `imgutil` initramfs hook.
MOK manager is placed on the boot media so secure boot key enrollment is possible from there.

### Cross-architecture image builds

`imgutil` can build images for an architecture other than the host's.

### `osdeploy fetch`

New subcommand that downloads distribution ISOs, with signature validation where it is
available, progress output, and tab completion.

### TPM PCR sealing

`encryptboot` accepts explicit TPM2 PCRs, `systemd-cryptenroll` is used where available, and
Ubuntu now seals to PCRs at first boot rather than during install, which is where the
measurements are actually stable.

### `net.extra_settings`

Passthrough network settings as semicolon-delimited key=value pairs, in the native syntax of
the deployed OS: nmcli properties, netplan keys, or wicked ifcfg variables.

### syncfiles cleanup

There were thirteen copies of `syncfileclient` in the tree, one per profile. There is now one,
in `common`, with the el7 profiles left on their own copy. It preserves ownership and
permissions without disturbing parent directories, applies chown before chmod, and reports
failures instead of discarding them.

### Stateless boot reports completion

Diskless boots report a `booted` status with a timestamp, so `nodedeploy` can tell a node that
finished from one that is still coming up.

## Console

### `nodeconsole -v`

Remote video console in the terminal, using a VNC client written into confluent instead of an
external dependency. Keyboard input, focus changes, desktop resize, and power commands work
from inside the session.

### vtbufferd

Communication moved to a unix domain socket, and the daemon is restarted automatically if it
exits instead of leaving `nodeconsole` broken with a zombie process behind it.

## Security

### Nodes can request a TLS certificate

A node can ask confluent for a TLS certificate through `/self/tlscert`. The validity is
controlled by the new `pubkeys.tls_lifetime` attribute, defaulting to 47 days.

### Unix socket permission controls

The permissions on the API socket are configurable, and so is its path, which used to be
fixed.

### webauthn rework

Passkey support was rebuilt on aiohttp and simplified to follow webauthn defaults, and a
username can now be established by passkey.

### License upload hardening

License filenames are reduced to their basename so they cannot traverse paths, and an upload
will not overwrite an existing file.

## Client and tooling

### `confluent2dnsmasq`

Generates dnsmasq DHCP configuration from confluent, using `ip route` for the listen address
and warning about conflicting entries. It replaces the `confluent2dnsmasqdhcp` name it was
briefly developed under.

### `confluentdbutil` additions

YAML for dump and restore alongside JSON, an `exclude` option, an alternate directory to
operate on, and a `showattrib` subcommand. Restore gives a clear error on a mismatched dump
format or a nonexistent tenant instead of an obscure failure.

### The CLI tools report failures

Client commands print an error rather than a traceback followed by usage text, and set an exit
code when a read fails. `nodeshell` gained a connect timeout.

### Man pages

Commands that had no man page have one now, including `confluent2ansible`, `confluent2dnsmasq`,
`confluent2lxca`, `confluent2xcat`, `dir2img`, `nodecertutil`, `noderename`, and
`nodegrouprename`. Rendering moved to pandoc.

## Project infrastructure

### CI

Every push runs shellcheck, ruff, `compileall`, and pyrefly. The pyrefly configuration is
deliberately narrow: it checks for coroutines that are never awaited and awaits on things that
are not awaitable. Those are the two mistakes an asyncio port makes that nothing else in CI can
see, and it is a blocking job.

### Versioning

Build versions come from a tracked `VERSION` file combined with `git describe`, so release
branches and development builds are both stamped correctly. Tags publish releases
automatically.

## Other fixes

Fixes not tied to the port: SSDP no longer ignores packets that do not closely follow another,
software RAID creation works with newer mdadm and hostname-prefixed md device names, `imgutil`
propagates image build failures instead of reporting success, a node cannot be named the same
thing as a group, collective rename of nodegroups works, and proxmox handles an unreachable
host and a powered down VM without hammering it.
